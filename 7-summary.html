一句话版本

IT4IT 是 The Open Group 的参考架构，它用一组端到端的价值流（v2.x 四条、v3.0 七条）、一组与产品解耦的功能组件、 和一套统一的服务数据对象，把 IT 从“工具孤岛”重新组织成一条可度量、可自动化的价值链。

速查表

是什么
The Open Group 发布的参考架构（Reference Architecture），不是流程模型、不是软件产品、不是一个部门。
解决什么
工具孤岛、点对点集成、端到端不可见、IT 无法按价值流算账。
怎么组织
价值流（干什么）→ 功能组件（需要什么能力）→ 数据对象（交接什么）。组件与工具解耦，工具可换、架构不动。
价值流（v2.x）
S2P 战略到组合 R2D 需求到部署 R2F 请求到履约 D2C 发现到纠正
价值流（v3.0）
Evaluate 评估 Explore 探索 Integrate 集成 Deploy 部署 Release 发布 Consume 消费 Operate 运营
关键交接物（v2.x）
Digital Service（立项产出）→ Service Release（交付产出）→ Service Contract（消费约定）→ Desired / Actual Service（运维度量）。
官方五概念
价值流、功能组件、服务生命周期数据对象、服务主干数据对象、关系。
版本现状
v2.0（2015）→ v2.1（2017）→ v3.0（2022）：引入数字产品与数字产品主干，价值流重组为 7 条（Evaluate / Explore / Integrate / Deploy / Release / Consume / Operate）。
与 ITIL
互补，不是替代。ITIL 给流程最佳实践，IT4IT 给承载这些流程的信息模型与架构地基。
怎么开始
从最痛的一条价值流切入，做“现状工具 → 功能组件”的映射，找出冗余、缺口与第一个该自动化的接口。

价值流对照：v2.x 四条 → v3.0 七条

v2.x 的每条流在 v3.0 里被拆到 1–3 条新流；反过来，Explore 同时承接 S2P 和 R2D 的部分职责。

v2.x管什么v3.0 对应
S2P决定该投什么Evaluate（投资决策）+ Explore（选型 / 产品定义）
R2D把它造出来Explore（需求 / 设计）+ Integrate（构建）+ Deploy（部署）
R2F让员工用上它Release（发布 Offer）+ Consume（下单 / 履约）
D2C保证它一直好用Operate（监控 / 诊断 / 修复）

完整的 7 条职责、交接物和 v2.x 阶段落点，见 第 3 站。
